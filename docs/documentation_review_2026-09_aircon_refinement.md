今回は数値計算コードを変更せず、説明の構成、数式の記号範囲、本文・表の書式を改訂した。

## 空調章の構成

技術文書v3.2第9章を次の順に再構成し、同じ本文を
[`aircon_model_and_control.md`](aircon_model_and_control.md) に保存した。

1. 空調機の接続と入力条件
2. 温度制御と運転停止
3. 顕熱と潜熱の処理量
4. 潜熱処理モデル
5. 能力制限と実効設定温度
6. 全館空調の風量制御
7. 同一時間ステップ内の反復
8. 消費電力と結果の読み方

設定相対湿度による理想除湿を、通常4方式に先立って適用される潜熱処理モデルとして位置づけた。
温度制御の室温拘束、吹出湿度の指定、室の湿気収支、電力モデルの役割を分け、
運転・最低能力・湿度更新の説明が異なる節で重複しないよう整理した。

## 実装との照合結果

| 確認事項 | 根拠 | 説明の修正 |
|---|---|---|
| 設定湿度の理想除湿 | `aircon_latent.cpp` の `estimateLatentProcess` | 吸込温度と設定RHから求めた吹出絶対湿度を指定。室RHを直接拘束しない |
| 潜熱処理の実行位置 | `aircon_controller.cpp` の能力・風量判定、`simulation_aircon_iteration.cpp` | 潜熱は能力比較の前に評価。再計算理由の優先順位とは区別 |
| 最低能力での継続 | `aircon_controller.cpp` の `holdAtMinimumCapacity` | 内部要求負荷の置換であり、全機種の実処理熱の固定ではない |
| 要求未達の境界値 | `aircon_airflow.cpp` の `selectFlowHeatBasis` | 温度差が0.5 Kを「超える」。境界値は含まない |
| 最低風量の条件 | 同ファイルの `computeTargetFlowFromProcessedHeat` | `0 < Q.min < Q.rtd` のときに下限補正 |
| 湿度目標の適用範囲 | `aircon_latent.cpp` | `none` より優先、目標以下は通常方式へ復帰、飽和制限なし、全熱能力判定は残る |

## 記号と表

本文の連続文字列になっていた添字、Unicodeを継ぎ足した記号、数式の添字へ括弧まで含めていた箇所を、
編集可能なWord数式として整理した。体積と体積流量、必要負荷と非負の処理量、物質移動係数と湿気コンダクタンスを区別した。
入力キーはコード書体を用い、式中の相対湿度は比率、JSONの設定RHは百分率と明示した。

表は列単位で配置を指定し、記号・単位列を中央、説明・入力キー列を左に統一した。
表内の独立数式段落をインライン数式へ変更して、数式だけ別の配置になることを防いだ。
縦位置、セル余白、繰り返し見出し、罫線、文字サイズも統一した。
