## 2. 文書照合で見つかった実装不一致

v1.7.5のリリースノートとengine文書は、ファンPQ方式で空調機nodeを圧力未知数にする必要を
明記していた。一方、builderの `process_aircon` はPQの4点をfanとpressure_lossへ展開するものの、
生成する空調機nodeへ `calc_p=true` を付与していなかった。このままでは圧力差とシステム抵抗から
PQの運転点を解くという説明と展開結果が一致しない。

今回、PQ方式では生成する空調機nodeの `calc_p` をtrue、固定流量方式ではfalseとするよう修正し、
builderテストへ空調機nodeと全体 `simulation.calc_flag.p` の確認を追加した。
利用者が手動で全体フラグだけを有効にしても、未知圧力nodeが無ければ同じ意味にならないため、
空調入力の展開時に局所フラグを設定する。

## 4. 適用上の制約

以下は現行実装のモデル化または数値制御上の制約であり、今回の文書改訂だけでは解消しない。

1. **停止中の風量**：OFF中はDUCT風量補正を行わず、停止直前の固定流量またはファン曲線が残り得る。
2. **負荷の代表点**：全館の負荷合計ではなく単一の `set_node` の負荷を基準とする。
   各室負荷に応じた独立配風制御ではない。
3. **遠隔制御**：`set` と `in` / `out` が離れる場合、設定維持負荷を直接得られず、
   コイル処理熱による代替値が風量基準になる場合がある。
4. **PQの目標と実風量**：負荷から得る値はファン速度比であり、実風量はダクト抵抗との交点で決まる。
   固定流量方式と同じ目標値を保証しない。
5. **離散的な最低能力制御**：ON/OFF周期と期間処理熱は時間刻み、熱容量、1.0 Kの再起動幅に依存する。

研究利用では、対象commit、空調仕様、固定流量またはPQの選択、圧損回路、時間刻み、
収束設定と検証した状態量を記録する。数値収束と実機制御・実測への妥当性は区別して評価する。
