# 全館空調（DUCT_CENTRAL）の風量・最低能力制御

対象はパッケージ v1.7.5更新版、実装 commit `83a724d376010a85da10163de4797636d795ea90`。
このガイドは利用者入力と結果解釈を扱う。反復手順の正本は
[engineの空調制御原則](../engine/docs/aircon_control_principles.md)と
[空調制御手順](../engine/docs/aircon_control_overview.md)である。

## 1. 制御が揃えようとする量

`DUCT_CENTRAL` は、空調の処理熱に応じて循環風量を変えるモデルである。
1タイムステップ内でON/OFF、能力制限、風量が相互に影響するため、solverは次の順で評価する。

1. ON/OFFと最低能力を判定する。
2. 最大能力を超える場合は、要求設定とは別の実効設定温度を調整する。
3. 運転が継続し、処理熱が安定してから風量を更新する。
4. どれかを変更した周では換気・熱を解き直し、次の周で再評価する。

前段が変わった周に後段まで同時更新しないのは、古い風量や温度場で求めた処理熱を
採用しないためである。最終結果は各量を独立に一度計算した値ではなく、外側反復の固定点である。

## 2. 負荷から目標風量を求める式

風量制御には、対象モードの定格能力 `Q.<mode>.rtd` [kW] と設計風量
`V_inner.<mode>.dsgn` [m³/s] が必要である。

$$
V = V_{\mathrm{dsgn}}
\operatorname{clamp}\left(
\frac{Q_{\mathrm{basis}}}{1000 Q_{\mathrm{rtd}}},0,1
\right)
$$

| 状態 | 基準熱量 $Q_{\mathrm{basis}}$ | 意味 |
|---|---:|---|
| 能力制限中 | 能力上限 | 実効設定を動かしている間は上限運転 |
| 要求未達 | 能力上限 | 暖房は要求より0.5 K以上低い、冷房は0.5 K以上高い |
| 設定維持中 | `abs(required_heat_w)` | 制御ノードの設定維持負荷。能力上限で制限 |
| 設定維持負荷が非有限 | 能力上限 | 数値的な代替 |
| `set_node` なし | 吸込・吹出から求めた処理熱 | 室温を固定しない場合だけ用いる |

能力上限は `Q.max`、無ければ `Q.rtd`、さらに無ければ `Q.mid` の順に解決する。
能力の最大値と風量の最大値は別である。風量比の分母は常に `Q.rtd`、上限は常に
`V_inner.dsgn` であり、`V_inner.rtd` や `mid` ではない。

全館空調の基準負荷は、建物全体の負荷合計ではなく `set` で指定した制御ノードの負荷である。
複数室の負荷配分や各吹出口の風量配分を個別に最適化する制御ではない。

## 3. 最低能力と再起動幅

設定温度を維持でき、必要負荷の絶対値が `Q.<mode>.min` 未満なら、連続してその小さな熱を
出せない機器として一度停止する。これは `DUCT_CENTRAL` だけでなく、`Q.min` を持つ
`RAC`、`CRIEPI`にも共通する。

停止後は、要求設定との差が次の片側幅を超えるまで再起動しない。

$$
\Delta T_{\mathrm{restart}}=
\max(\text{空調温度許容値},1.0\ \mathrm{K})
$$

ただし、停止側の自由室温が既に再起動幅の外に出る場合は、ONとOFFを往復する固定点を避けるため、
ONのまま `Q.min` を処理する。このとき風量も `Q.min/Q.rtd` に対応する最低風量となる。
ちょうど `Q.min` は運転可能である。`Q.min` が無い機種にはこの最低能力停止を適用しない。

ここでの1.0 Kは再起動ヒステリシスである。前節の0.5 Kは、要求未達時に風量基準を
能力上限へ切り替える判定であり、目的が異なる。

## 4. 必要な機器仕様

次は性能値の構造を示す抜粋である。数値は入力形式を説明する例であり、特定機器を表さない。

```python
duct_spec = {
    "Q": {
        "cooling": {"min": 2.7, "rtd": 7.7, "max": 8.0},
        "heating": {"min": 2.7, "rtd": 7.8, "max": 8.5},
    },
    "P": {
        "cooling": {"rtd": 2.4},
        "heating": {"rtd": 2.1},
    },
    "P_fan": {
        "cooling": {"rtd": 0.24},
        "heating": {"rtd": 0.24},
    },
    "V_inner": {
        "cooling": {"rtd": 0.46, "dsgn": 0.36},
        "heating": {"rtd": 0.46, "dsgn": 0.36},
    },
}

input_data["aircon"] = [{
    "key": "全館空調機",
    "set": "LDK",
    "in": "還気",
    "out": "吹出",
    "outside": "外気",
    "pre_temp": vt.schedule.pre_tmp["region6"]["全館空調"],
    "pre_rh": vt.schedule.pre_rh["region6"]["全館空調"],
    "mode": vt.schedule.ac_mode["region6"]["全館空調"],
    "model": "DUCT_CENTRAL",
    "vol": 0.36,
    "ac_spec": duct_spec,
}]
```

`vol` はm³/sである。固定風量方式では初回の枝風量となり、その後、反復が安定すると負荷追従値へ
置き換わる。`Q.rtd` または `V_inner.dsgn` が無いモードでは負荷追従風量を計算しない。

## 5. 固定風量方式とファンPQ方式

### 5.1 固定風量方式（既定）

PQの4点を指定しなければ、builderは次の2枝を `fixed_flow` として生成する。

| 枝 | 設定される風量 |
|---|---:|
| `in → 空調機` | $+V$ |
| `空調機 → out` | $+V$ |

`in == out` でも吹出側を負にしない。両枝は同じ循環を表すためである。
固定流量は圧力差から決まる実風量ではないので、利用者は循環回路全体の流量収支を確認する。

### 5.2 ファンPQ方式

`p_max`, `p1`, `q1`, `q_max` をすべて指定すると、吸込枝は `fan`、空調機から吹出への枝は
`pressure_loss` になる。`vol` を同時に指定してもファン枝には用いない。

```python
input_data["aircon"][0].update({
    "p_max": 180.0,  # Pa
    "p1": 120.0,     # Pa
    "q1": 0.20,      # m3/s
    "q_max": 0.42,   # m3/s
    "area": 0.08,    # m2、空調機から吹出への短い接続
    "k_total": 1.0,
})
```

4点の一部だけを指定するとbuilderはエラーにする。入力値には
`p_max > 0`, `q_max >= 0`, `q1 >= 0`, `0 <= p1 <= p_max`, `q1 <= q_max` が必要である。
運転負荷から求めるのは速度比 $\lambda=V/V_{\mathrm{dsgn}}$ であり、定格PQを相似則で縮小する。

$$
q'=\lambda q_{\mathrm{rated}},\qquad
p'=\lambda^2 p_{\mathrm{rated}}
$$

実風量は縮小したファン曲線とダクト抵抗曲線の交点である。このため、式で得た目標風量と
必ずしも一致しない。builderはPQの4点が揃うと空調機ノードを圧力未知数にし、全体の
`simulation.calc_flag.p` も有効にする。吹出から各室、各室から還気までの圧損枝は利用者が
構成する。複数室へ同じ目標風量を重ねて与えず、抵抗網で総風量を配分する。

## 6. 結果を確認する手順

研究・設計用途では、少なくとも次を確認する。

1. `vent_flow_rate` で吸込と吹出の総流量が同じ循環量になっているか。
2. 設定維持、要求未達、能力制限の時刻を分け、風量基準が意図した状態と対応するか。
3. `aircon_sensible_heat` と `aircon_latent_heat` の和、`Q.min`、`Q.rtd`、`Q.max` の単位を揃えたか。
4. PQ方式では圧力・流量収支と実風量を確認し、固定風量方式と同じ値になると仮定しないこと。
5. 時間刻みを変え、ON/OFF回数、期間処理熱、消費電力量、室温逸脱が安定するか。

期間電力量は出力がWなら、時間刻み $\Delta t$ [s] に対して
$E[\mathrm{Wh}]=\sum P\Delta t/3600$ とする。瞬時値の一致だけでなく、周期的な最低能力運転が
期間集計へ与える影響も確認する。

## 7. 現行実装の制約

- OFF中は風量補正を行わないため、停止直前の固定流量またはファン曲線が残る場合がある。
- 全館の総負荷や各室負荷から独立に風量配分する機能ではなく、1つの `set` ノードが基準である。
- 遠隔 `set` では設定維持負荷を直接得られず、コイル処理熱による代替になる場合がある。
- PQ方式の実風量はシステム抵抗に依存し、目標風量は保証値ではない。
- 最低能力のON/OFFは離散時間で評価するため、時間刻みと熱容量により周期と期間平均が変わる。

これらは数値安定性と現行モデル化の境界であり、実機の制御ロジックや部分負荷効率を
自動的に再現する保証ではない。計算条件、対象commit、検証した観測量を結果と併記する。
