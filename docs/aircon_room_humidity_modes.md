# 室温・室湿度の制御モード

`aircon[].control_mode` は温湿度の制御目的を指定する。省略時は
`temperature_priority` で、室温要求に従って運転する。`mode`（暖房・冷房・停止）、
`model`（COPモデル）、`ac_spec.latent_method`（従来の潜熱処理方式）とは別の指定である。

| control_mode | 冷房時の動作 |
|---|---|
| `temperature_priority` | 室温要求で運転し、`latent_method` に従って冷却に伴う除湿だけを行う。`pre_rh` は室RHの未達評価に使い、吹出湿度の強制指定や湿度単独の運転はしない。 |
| `humidity_priority` | 室湿度の要求でも運転する。理想飽和コイルによる冷却除湿を行い、室温を設定温度から `max_overcooling` K まで下げられる。再熱は行わない。 |
| `temperature_humidity` | 室温設定と室RH上限の両立を目指す。理想コイルで除湿し、必要に応じて再熱する。冷却コイル能力が不足する場合は温度を優先し、残る湿度超過を出力する。 |

新しい2モードの `pre_rh=60` は、**設定対象室のRHを60％以下にする除湿要求**を意味する。
乾燥時には加湿しない。湿度優先のRHは実際の室温で評価する。
温湿度満足の必要水分量は要求設定温度で評価し、出力するRH未達は実際の室温による。

```json
{
  "key": "AC",
  "set": "LD",
  "in": "return",
  "out": "supply",
  "outside": "outside",
  "mode": "COOLING",
  "model": "RAC",
  "pre_temp": 26.0,
  "pre_rh": 60.0,
  "control_mode": "temperature_humidity",
  "max_overcooling": 2.0,
  "min_coil_temperature": 5.0,
  "reheat_cop": 1.0,
  "vol": 0.1
}
```

これは既存入力の空調部分の抜粋。別途 `ac_spec`、参照ノード、換気・熱回路を指定する。
`calc_flag.x=true`、設定対象室の `calc_x=true` / `calc_t=true` が必要。
新モードでは `COOLING` / `HEATING` / `OFF` を明示し、`AUTO` は使用しない。
暖房時は従来の温度制御、停止時は除湿を行わない。各時刻の設定温度・湿度を使用する。

## 理想設備としての前提

新しい2モードは機種の除湿性能を再現する制御ではなく、**理想飽和コイル**による比較用モード。
新モードの `latent_method` は `ideal_coil`（省略時の既定値）を指定する。`none` / `rh100` も同義として受け付ける。95％法・BF法・コイル面積法との組合せは未対応のため、入力エラーにする。これらの物理モデルは温度優先で使用する。
吸込・吹出・設定対象室は別室にできる。除湿目標は湿気回路網を用いて、発湿、外気流入、
水分蓄積、材料との水分交換を含めて算定する。室湿度の結果値を直接固定・切り詰めない。

`max_overcooling` の既定値は2 K（0～10 K）。温度が下限より低いとき、湿度優先は
除湿のための加熱を行わず、湿度未達を残す。`min_coil_temperature` の既定値は5℃（0～20℃）。
温湿度満足は理想再熱設備を仮定する。`reheat_cop=1` は電気ヒーター相当で、
再熱電力を冷却機の消費電力に加える。再熱能力は無制限とする。
温湿度満足では、冷房期間でも室温が設定より低ければ理想再熱で補い、乾燥時は加湿しない。
機器の `Q.cooling` 能力上限は、再熱前の冷却コイルの顕熱＋潜熱に適用する。
`model=IDEAL` は従来どおり冷却COPを持たないため、機器電力量の比較にはCOPモデルを指定する。明示した再熱の電力はIDEALでも別途計上する。

DUCT_CENTRALの新モードは、顕熱要求がゼロでも除湿風量を確保するため、運転中の
固定流量循環を `V_inner.cooling.dsgn` に保つ。PQファンは設定された圧力・流量関係で求める。
吹出RH≦100％、水分収支、全熱能力の最終受理判定は従来と共通である。

## 出力と成功判定

| artifact | 内容 |
|---|---|
| `aircon_reheat` | 再熱量 [W]。既存の冷却顕熱・潜熱には含めない。 |
| `aircon_room_rh` | 設定対象室の実際の相対湿度 [%] |
| `aircon_humidity_unmet` | 冷房時のRH上限超過 [percentage points]。停止・暖房時は0。 |
| `aircon_temperature_unmet` | 運転モード有効時の要求設定温度との差の絶対値 [K]。停止時は0。 |

`status=ok` は数値解と物理制約が成立したことを表す。温湿度設定の達成とは区別する。
能力、過冷却下限、コイル条件、送風・接続条件のために目標が達成できない場合は、
未達量をそのまま記録する。年間の未達時間は、用途に応じた温度・湿度の許容帯を決めて集計する。

検証は `engine/tests_py/test_room_humidity_control.py`。従来条件の回帰検証も併用する。

## 旧「理想60％」条件の移行

2026-11-14の修正で、温度優先の `pre_rh` による独立した吹出湿度の指定を廃止した。
旧方式は、冷却が小さくても室設定温度・RHから換算した水分量まで除湿でき、再熱なしの
冷却過程として整合しなかった。温度優先では `pre_rh` の有無・値で処理量や電力は変わらず、
室RH未達の評価だけが変わる。`latent_method="none"` は吹出の飽和防止に必要な凝縮のみ行う。
湿度60％を制御目標にする比較には `humidity_priority` または `temperature_humidity` を明示する。
旧「理想60％」の年間結果・電力量は修正後の結果ではないため、比較には再計算が必要である。
なお、DUCT_CENTRALの電力モデルには従来から顕熱と潜熱の両方を渡している。
本修正は電力を後付けする処理ではなく、その入力となる冷却・除湿過程の修正である。
