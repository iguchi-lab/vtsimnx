# v1.7.4

v1.7.3 以降の空調・湿度まわりの安定化と、成果物読込みの不整合修正をまとめるパッチリリースである。

## 主な変更

- 空調ノードを湿度の固定境界（`calc_x=false`）として扱い、`SupplyHumidityChanged` による外側ループ振動を抑えた。
- OFF / 非冷房の還気循環を湿度移流から除外し、大風量還気による室湿度の過乾燥ロックを防いだ。冷房 ON のみ吹出境界として除湿を反映する。
- 外側ループの湿度連成前に、OFF / 未初期化の空調 `current_x` を吸込湿度へ同期する。
- 吹出湿度の外側再計算に床 `1e-4 kg/kg(DA)`、温度バンドに床 `0.5K` を導入し、微小ドリフトでの再計算過多を抑えた。
- 冷房時の理想相対湿度制御（`pre_rh`）を追加した（過湿時は `supplyX = absolute_humidity(T_in, pre_rh)`）。
- Python クライアントで `schema.series.*.keys=[]`（列数 0・bin 0 バイト）を 1 列スカラーと誤解釈していた不整合を修正した。
- 上記に合わせて `engine/docs`（空調制御・湿気 Phase1・builder JSON）を更新した。技術文書 v3.2 の DOCX/PDF 反映は後続改訂で行う。

## 確認結果

- C++: `test_humidity_enable_zero_cap` / `test_aircon_controller` / `test_moist_enthalpy_advection` / `test_parser_nodes_mode`
- Python: artifacts 読込み関連テスト、builder の aircon テスト

## 利用時の注意

- 技術文書 DOCX/PDF（v3.2）への今回の実装反映は未実施。当面の正本は `engine/docs/` を参照する。
- `pre_rh` は冷房運転中かつ室内絶対湿度が目標を超える場合のみ有効で、能力上限・機種特性は見ない理想除湿である。
