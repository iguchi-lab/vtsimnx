# 仕様書の執筆要領・節テンプレート

[全体目次](README.md)に戻る。

## 1. 記述の原則

読者が入力条件から出力までの処理を再現できるように記す。計算方法は文章・数式・条件表で定義し、コードへのリンクだけを本文の代わりにしない。操作例、導出の解説、実装の配置は規定と区別する。

「…は、式 (7-1) により求める。」「…の場合は、…とする。」の文体を用いる。何を入力とし、どの条件で、何を求めるかを式の直前に示し、直後に記号の意味と単位を記す。

本仕様書は対象 commit の実装を基準にする。既存文書とコードが異なる場合は実装に合わせて本文を記述し、差異を付録に残す。近似・制約・例外も実際の処理を記載する。未実装の提案を現行仕様に含めない。

## 2. 各節の共通構成

| 項目 | 記載内容 |
|---|---|
| 適用範囲 | 対象、前提、計算フラグ、他節との関係、対象外 |
| 参照資料 | 実際に用いる規格・論文・他節及び対象版 |
| 用語の定義 | 固有の用語。共通用語は第一章を参照 |
| 記号及び単位 | 物理量、添え字、正方向、基準状態 |
| 入力条件 | 型、単位、範囲、必須性、既定値、時系列、排他条件 |
| 計算・変換方法 | 支配式又は変換規則、分岐、係数、処理順序 |
| 数値処理 | 離散化、初期値、境界、収束、履歴確定。非該当は理由を記載 |
| 出力 | 名称、単位、配置、符号、時刻との対応 |
| 例外及び制約 | エラー、警告、補正、フォールバック、未対応 |
| 検証 | 入力条件、期待値、許容差、対応テスト、確認結果 |
| 実装対応・改訂履歴 | 対象版、commit、実装箇所、確認日、変更の影響 |

## 3. 表と番号

式・表・図は章単位で `(7-1)`、`表 7-1`、`図 7-1` とする。一般式と実装の離散式を別々に示す。

### 入力項目表

| 項目のパス | 意味 | 型・形状 | 単位 | 必須・既定値 | 有効範囲・条件 | 根拠 |
|---|---|---|---|---|---|---|
| 記入 | 記入 | スカラー／配列等 | 無次元も明記 | 未指定・null・空配列を区別 | 境界値・時系列長も記載 | 実装／テスト |

### ビルダー変換表

| raw JSON の項目・条件 | 変換規則 | 計算用 JSON の項目 | 単位換算 | 生成・削除・上書き | 警告・エラー |
|---|---|---|---|---|---|
| 記入 | 適用順序を含める | 完全なパス | 換算なしも明記 | 命名規則も記載 | 発生条件を記載 |

### 仕様確認表

| 仕様 ID | 条件と期待結果 | 実装 | テスト | 確認方法・結果 | 未確認事項 |
|---|---|---|---|---|---|
| SPEC-04-001 等 | 一つの判定可能な要件 | ファイルと関数名 | ファイルとテスト名 | 読解／実行を区別 | なければ「なし」 |

テストの存在だけでは検証済みとしない。式の番号と仕様 ID は別に管理する。

## 4. 分野別に必ず記載する事項

- 換気：圧力基準、流量の正方向、逆流時の分岐、収支の収束指標。
- 熱：温度単位、熱流の正方向、容量と時間刻み、履歴値と反復値の区別。
- 湿気：乾き空気基準等の質量基準、湿度換算、飽和時の処理、水分と潜熱の対応。
- 濃度：濃度の基準・単位、発生量・沈着率・除去効率の次元、移流元、物質収支。
- 電力：W と kW、電力と電力量、積分条件、COP の定義、ファン・補機の算入範囲。
- 連成：評価時点、更新対象、終了条件、時間積分基準、履歴確定時点。

未対応機能の式を掲載する場合は将来案と明示する。原理的に計算できることと実装済みであることを混同しない。

## 5. 節テンプレート

```markdown
# 第○章 ○○　第一節 ○○

文書版：草稿 0.1
対象プログラム・commit：未確認
確認日：未確認
状態：本文作成中

## 1. 適用範囲
対象、前提、適用外の条件。

## 2. 参照資料
根拠資料及び対象版。

## 3. 用語の定義
共通定義の参照先及び固有の用語。

## 4. 記号及び単位
記号・意味・単位・正方向・添え字の表。

## 5. 入力条件
入力項目表。

## 6. 計算方法又は変換方法
一般式、実装の式、分岐条件、処理順。

## 7. 数値処理及び境界条件
初期化、時間離散化、反復、収束、履歴。

## 8. 出力
項目、単位、符号、時刻。

## 9. 例外及び適用限界
補正、警告、エラー、未対応。

## 10. 検証及び実装対応
仕様確認表、手計算又は変換前後の照合例。

## 11. 改訂履歴
変更日、対象版、理由、結果と互換性への影響。
```

## 6. 確定条件

入出力・式・分岐・単位・例外が記載され、対象 commit の実装と対応付けられ、重要な境界条件の検証範囲と未検証範囲が明示されていることを確認する。未解決の仕様差異を残した節を「確定」と表示しない。

## 7. GitHub・スマートフォンでの数式表示

独立した数式は、equations ディレクトリの SVG 画像を Markdown の画像として掲載する。GitHub の数式描画に依存せず、文字の配置を画像内に固定する。白背景・濃色文字により、ライト・ダークの両表示でコントラストを確保する。画像は元の寸法比を保って縮小され、必要に応じて画像を開いて拡大できる。

正本の LaTeX は同名の .tex ファイルに保存し、本文から「数式ソース」としてリンクする。式番号も .tex の tag に保持する。manifest.json は章・ファイル・番号の対応、render.cjs は再生成用スクリプトである。数式を改訂する場合は .tex と SVG を同時に更新する。表示修正のために係数・符号・演算順を変えない。

再生成には Node.js と mathjax-full 3.2.2 を使用する。ライブラリはリポジトリ外の作業フォルダーへ導入し、その node_modules を NODE_PATH に指定して、リポジトリ直下で次を実行する。

```text
node docs/specification/equations/render.cjs
```

生成時に TeX エラー、外部参照・スクリプトの混入を検査する。SVG は数式の文字をパスとして保持し、外部フォントを必要としない。改訂時は狭い画面幅に縮小した画像も確認する。

表内では Unicode の添え字、abs(...) 等のテキスト表記を使用する。未エスケープの縦線は Markdown の列区切りになるため使用しない。
