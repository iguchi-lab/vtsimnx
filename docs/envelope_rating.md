# 入力面から住宅の UA・ηAC・ηAH を求める

室温計算に渡す `input_data["surfaces"]` を使い、気象系列やソルバーの実行前に外皮を評価できます。標準住宅では床断熱の `default`（等級4）・`grade5`～`grade7`、基礎断熱の `foundation4`～`foundation7` に対応します。

```python
import json
from pathlib import Path
import vtsimnx as vt

# 初回に、make_caseで選んだ住宅と同じモデルの評価条件を書き出す。
path = Path("foundation5-rating.json")
if not path.exists():
    template = vt.standard_house.rating_template("foundation5", region=6)
    path.write_text(json.dumps(template, ensure_ascii=False, indent=2), encoding="utf-8")
```

JSONの評価条件を確認し、必要な設計値を記入して、次のセルで集計します。

```python
assessment = json.loads(path.read_text(encoding="utf-8"))
r = vt.envelope_performance(input_data, assessment)
print(r["UA"], r["eta_AC"], r["eta_AH"])
import pandas as pd
display(pd.DataFrame(r["parts"]))
```

- **窓・ドア**　`U` は枠と表面熱抵抗を含む開口部全体の熱貫流率［W/(m²·K)］です。等級5～7にはモデル元のSimHeat部位表の値が入ります。障子などの付属部材の扱いを含め、採用する評価仕様と照合してください。等級4の窓は個別空調のUA計算書と同じU=4.65、金属製など・一般複層・付属部材なし（ηd=0.632）です。窓の `eta_d` は枠込みの垂直面日射熱取得率（0～1）です。季節で付属部材等が異なる場合は `eta_d_C`・`eta_d_H` を個別に設定できます。標準住宅の既定は取得日射熱補正係数の定数法（冷房期0.93、暖房期0.51）。別の方法で評価した窓は `f_C`・`f_H` を上書きします。SimHeatのカーテン込みの放射・対流成分や時刻別の日向率とは定義が異なります。
- **床・基礎**　床断熱では通気する床裏に面する床を H=0.7 とし、基礎断熱では床下を断熱境界内に含めます。土間は面積を分母に加算し、熱損失は `lines` に区間別の中心線長さ［m］（省略時の推定は下記）、`psi`［W/(m·K)］、温度差係数 `H` を入力します。標準住宅は基礎壁を面として評価する方式です。これに対応する土間外周ψを選んでください。玄関土間と床下の間など、隣接条件が異なる区間は行を分けます。
- **一般部位**　`parts` の各項目は同じ部位の並列断面を `keys` で参照します。面積比でUを加重し、面積は断面を合算して0.01 m²単位に丸めます。層構成は室内側から並べ、熱抵抗は厚さ［m］÷熱伝導率または明示した `thermal_resistance` を使います。外気に連通する通気層で加算を止めます。基準用の熱抵抗・施工補正がシミュレーションと異なる部位には評価用の `U` を明示してください。外壁等の日よけ効果係数 `gamma_C`・`gamma_H` は既定1、日射吸収率 `absorptance` は既定0.8です。
- **任意の住宅**　`assessment` はモデル本体と独立した辞書です。全入力面を `parts` か `excluded` に一度ずつ割り当てます。`kind` は wall、roof、ceiling、floor、window、door、slab。層からUを求める面に外気側表面抵抗の区分 `outside`（真偽値）を設定します。`directions` は外気に面する方位（N～NW、屋根はTop、下面はBottom）のリスト、日射の当たらない隣接空間は空リストです。線熱橋は `kind="bridge"` とし、複数方位の平均では日射の当たらない側を `None`（JSONのnull）とします。土間外周は `kind="perimeter"` です。
- **結果**　UAは小数第2位に切り上げ、ηACは小数第1位に切り上げ、ηAHは小数第1位に切り下げます。8地域のηAHは対象外です。`A_env`［m²］、`q`［W/K］、`m_C`・`m_H`［m²］と部位別内訳も返します。

計算根拠は建築研究所の[第三章第二節「外皮性能」](https://www.kenken.go.jp/becc/documents/house/3-2_260401_v13.pdf)、[第三節「熱貫流率及び線熱貫流率」](https://www.kenken.go.jp/becc/documents/house/3-3_261116_v28.pdf)、[第四節「日射熱取得率」](https://www.kenken.go.jp/becc/documents/house/3-4_261001_v21.pdf)です。

## 窓の評価仕様

一重構造の窓では、評価条件の窓の行、または元入力の各窓面に次の3項目を設定できます。評価条件に値を指定すると面の設定に優先します。

| 項目 | 選択できる値 |
|---|---|
| `frame_type` | 木製・樹脂製、木・樹脂と金属の複合、金属製熱遮断、金属製、金属製など、枠の影響なし |
| `glass_type` | 単板、一般複層、一般三層、Low-E二層・取得型、Low-E二層・遮蔽型、Low-E三層・取得型、Low-E三層・遮蔽型、Low-E三層・複数膜・取得型、Low-E三層・複数膜・遮蔽型 |
| `attachment` | なし、和障子、内付け遮蔽、外付け遮蔽 |

「なし」は付属部材なしを明示します。レースカーテンの室温計算設定とは独立です。二重窓や製品値を用いる場合は枠込みのηdを直接入力してください。優先順位は季別の直接値、共通の直接値、仕様による算定です。

空欄があれば指定済みの項目に合う付録C表1の候補から冷房期は最大、暖房期は最小のηdを採用し、窓名・不足項目・採用値を警告します。これは比較時の保守的な仮定です。全項目が空欄なら冷房期は0.88、暖房期は0.0576になります。8地域では冷房期だけを評価します。採用値は部位別結果の `eta_d_C` と `eta_d_H` で確認できます。

### 窓の入力例

評価用JSONの該当する窓行に次の3項目を加えます。等級4の個別空調計算書では和室も含めて付属部材なしです。

```json
{"frame_type": "金属製など", "glass_type": "一般複層", "attachment": "なし"}
```

ガラスのηg = 0.79、枠係数 = 0.80 より ηd = 0.632。取得日射量補正係数と地域別方位係数はこの後に適用します。[建築研究所・第三章第四節 付録C 表1・式(1)](https://www.kenken.go.jp/becc/documents/house/3-4_261001_v21.pdf#page=15)

### 同じ窓仕様を室温計算に使う

`vt.window_properties` は、評価条件に転記する `rating` と、室温計算の窓面に転記する `surface` を返します。次は金属枠・一般複層・中空層6 mmの例です。対流割合0.25は入力例の仮定です。

```python
import vtsimnx as vt

w = vt.window_properties(frame_type="金属製", glass_type="一般複層", gap_mm=6,
                         attachment="なし", convective_fraction=0.25)
rating_part = {"keys": ["子供室1->外部||南窓"], "kind": "window", "H": 1,
               "directions": ["S"], **w["rating"]}
surface = {"key": rating_part["keys"][0], "part": "glass", "area": 2.0,
           "solar": [500.0], **w["surface"]}
```

この例では `U=4.65`、`eta_d=0.632`、`SCC=0.158`、`SCR=0.474` です。1時間の例の窓面入射日射500 W/m²に対して、空気に158 W、室内表面に474 Wを配分します。床と壁・天井に半分ずつ配り、各群内は面積×吸収率で按分します。一方の群だけがある室ではその群が全量を受けます。日影を考慮する場合、`solar` には遮蔽後・ガラス透過前の窓面入射日射を渡します。透過済みの日射にηを掛けると取得率が二重に掛かります。

- Uの仕様表は木製・樹脂製、複合、金属製熱遮断、金属製の4区分です。複層窓のガラス間の空隙には厚さ `gap_mm` を、Low-Eでは `gap_gas="ガス"`（断熱性ガス）または `"空気"` を指定します。三層の区分では各中空層が条件を満たす厚さを使用します。表にない仕様や枠の詳細が不明な場合は設計値 `U` を指定します。外皮評価用JSONでも窓の `U` を空欄にして同じ仕様を指定できます。[住宅の設計用計算例・付録B表3の実装](https://github.com/BRI-EES-House/pyhees/blob/main/src/pyhees/section3_3_b.py)
- 仕様表の和障子は、素の窓のUと付加抵抗0.18 m²K/Wを加えた閉鎖時のUの平均を採用します。時刻別計算でもこの平均値を一定とするモデルです。開閉状態を固定する場合はその状態の窓全体の `U` を指定できます。直接指定のUには付加抵抗を再適用しません。その他の対応する日射遮蔽部材には断熱効果を加算しません。[開口部の付属部材の扱い・式(6)(7)](https://github.com/BRI-EES-House/pyhees/blob/main/src/pyhees/section3_3_5.py)
- `whole_window_u` は両側表面を含む熱貫流率です。等価回路では窓本体の抵抗を `1/U − 1/alpha_i − 1/alpha_o` とし、両側の抵抗を1回ずつ接続します。室内表面間の長波放射はこの窓では総合熱伝達率に含めます。既定の等価表面抵抗は室内0.11、室外0.04 m²K/Wというモデル仮定です。既存の窓面を移行するときは従来の `u_value` または `layers` を除き、対流のみの `alpha_i`・`alpha_o` も外すか、総合熱伝達率に置き換えます。窓本体の抵抗が正にならない入力はエラーになります。
- `convective_fraction` は取得熱に占める対流割合（0～1）です。SimHeatに同一仕様の係数があれば `SCC / (SCC + SCR)` を使用できます。測定値などの既存係数をそのまま採用する場合は、割合に代えて `SCC` と `SCR` を対で渡します。この場合は元の合計を保持します。評価用ηとの比較には日射と面積の基準をそろえてください。

## 基礎・土間外周の長さと線熱貫流率

基礎の仕様と隣接空間が同じ区間ごとに `lines` に1行を入力します。設計図があれば基礎の心の水平長さを `length`［m］として使用します。区間の熱損失は **L × ψ × H**［W/K］で、UAの分子に加算します。土間の水平面積は外皮面積に算入します。[建築研究所・第三章第二節 式(4)、付録A.3・B](https://www.kenken.go.jp/becc/documents/house/3-2_260401_v13.pdf)　[第三章第三節 熱貫流率及び線熱貫流率](https://www.kenken.go.jp/becc/documents/house/3-3_261116_v28.pdf)

| 入力の優先順 | 値と単位 | 計算例 |
|---|---|---|
| 1. `length` | 区間の水平長さ［m］ | 12.5 を指定すると L = 12.5 m |
| 2. `wall_area` | 対応する基礎立上りの片面の見付面積［m²］ | 4.0 m² ÷ 0.4 m = 10 m |
| 3. `wall_keys` | 同一区間の立上りを表す入力面のキー一覧 | 面積を合計して 0.4 m で割る |

2と3は、立上り高さを一律 **0.4 m** と仮定するVtSimNxの推定方法です。基準で指定された外周長の算定式ではありません。推定時は区間名、面積、採用長を警告し、結果の `parts` に `length`、`length_source` と使用面積を記録します。土間の水平面積や立上りの両面を推定面積に入れると長さを過大評価します。同じ区間は一度だけ指定してください。

```json
{"name":"外気側の立上り","kind":"perimeter","length":null,"wall_area":4.0,"psi":0.5,"H":1}
```

この数値例は L = 10 m、熱損失 = 5 W/K です。ψ［W/(m·K)］は採用する基礎仕様に対応する値を入力します。Hは隣接空間による温度差係数です。長さも参照面積も不明な場合は設計値の入力が必要です。

標準住宅の基礎断熱テンプレートは床下の四方の基礎外壁を参照します。床断熱テンプレートは玄関土間の外気側と換気床下側を分け、後者は「ホール-床下」の立上りを参照します。外気側の玄関立上りは独立した面積データがないため、その区間の長さまたは立上り面積を入力してください。既存のJSONには `wall_area` または `wall_keys` を追記できます。
