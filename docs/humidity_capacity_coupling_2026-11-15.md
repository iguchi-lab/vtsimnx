# 複数台湿度制御の能力制限と収束（2026-11-15）

基準は PR #37 の `94517c8`。対象は #34 / #35 の複数台制御。構想項目やAPIの変更は含まない。

## 再現した問題

連通2室に別々の空調を置き、室温26℃、RH目標60%と58%、片方の最大冷房能力1 kW、もう片方20 kWで検証した。

- 温湿度満足では、潜熱だけが能力制限された機器を「目標達成可能」として他機器の要求計算に使っていた。余力のある室も最終RHが59.75336%となり、58%を満たさなかった。
- 湿度優先では、能力制限の探索中に他機器が設定を動かし、探索区間が古くなって未収束となった。
- 能力上限内に入った後に他室の負荷が変わると、湿度未達でも余った能力を再利用しない経路があった。
- 探索候補の移動が小さいだけで終了すると、連成で移動した根に対するコイル温度誤差が残る場合があった。

## 修正

1. 潜熱の能力制限を室温制御の状態と分けて保持し、他機器の湿度応答行列には制限機器の実際の吹出絶対湿度を使用する。状態の変化も再計算の理由に含め、停止・次時刻で解除する。
2. 能力探索中は自由な湿度制御の温度変更を待たせる。探索終了・停止で古い区間を解除する。
3. 温度と残差の実測点を使い、区間内に制限した補間で候補を選ぶ。古い区間が縮んでもコイル温度誤差が残る場合は、現在点の近くで探索を再開する。
4. 他機器の湿度制御が落ち着いてから余力を再評価する。湿度要求が残れば能力探索を再開し、要求が下がっていれば湿度制御へ戻す。

物理収支・能力・コイル温度の許容誤差、反復上限は緩和していない。能力不足による湿度未達は出力に残す。

## 検証

回帰試験は、能力0.4/1/2 kW、機器順序、湿り空気エンタルピーの有無、停止・再起動、外気乾湿切替、3台連成、2台とも能力不足、rh95/BF/コイル面積方式を含む。目標RH、能力上限と余力利用、独立の水分収支を検査する。自由な機器の達成を調べる試験では、コイル下限による別の制約に当たらない風量・下限温度を明示する。

- Python engine: 520件合格（うち湿度制御90件）。C++: 28件合格。ruff、差分検査も合格。
- 元のコイル下限5℃の再現入力: 両モードで完走。温湿度満足の2室目は58.00%。湿度優先の初期1時間はコイル下限により59.319%で、以降は58.00%。機器の能力不足を数値未収束にしない。
- 年間合成気象: 両モードとも8,760時間、物理制約・自由な制御点のRH精度を合格。湿度優先の最大RH誤差は0.001576ポイント、温湿度満足はfloat出力上0ポイント。
- 既存住宅の年間24条件: 検証中。完走・保存量・圧力収支・受入残差・容量・電力・吹出RHを検査する。
